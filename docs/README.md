# The docs, and which to read

Start with `CLAUDE.md` at the repo root (the rules and the owner's picture of
the app), then `docs/HANDOFF.md` (the product brief). To find code, use
`docs/CODEMAP.md`.

## Current: kept up to date

| Doc | What it is for | When to read it |
|---|---|---|
| `HANDOFF.md` | The product brief: purpose, principles, design language, how to work, technical map | First, in a new session |
| `ASKS.md` | Every ask the owner has made, dated; the Open list is the work | Before proposing anything; for "what's next" |
| `EXPECTATIONS.md` | What every feature is meant to do, in detail | Before changing a feature (and update it after) |
| `FEEDBACK.md` | The owner's feedback, each broken down into checks | Before design work; with the `owner-feedback` skill |
| `RIPPLES.md` | What else to check when something changes | Before calling a change done |
| `CODEMAP.md` | Every source file in one line, and every plan by title (generated by `npm run codemap`) | To find where something lives |
| `evidence.md` | The learning science behind the design | When a feature rests on a claim about learning |
| `supabase.sql` | The database: tables, row-level security, functions | Sync, share links, accounts, reminders |
| `rename-plan.md` | Renaming the repo to arborous (on hold) | Only if the owner asks for the rename |
| `../sim/FINDINGS.md` | Every simulator result, with numbers | Before changing scheduling, Review, Learn |
| `../prompts/generator.md` | The prompt the app hands out to make a lecture | Only when the task is the prompt |

## Plans: `proposals/`

One file per plan, each with the options weighed and the reason one won
(listed by title in `CODEMAP.md`). A plan records the reasoning at the time;
whether it is built is in `ASKS.md` and `EXPECTATIONS.md`.

## Historical: `archive/`

Finished records, kept for their reasoning, not to act on.

- `archive/history.md`: what was built each session from 2026-09 to
  2026-11, with the plans of the time (once HANDOFF's §0, §4 and §6).
- `archive/audits/`: past audits of the code, the prompt and the learning
  logic.
- `archive/briefs/`, `archive/prompts/`: the briefs and session prompts
  those audits and the 2026-11-16 grading ran from.
